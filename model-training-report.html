❗ ความเข้าใจที่ต้องเคลียร์ก่อน

  • การเทรน ไม่ได้ใช้ SSense ช่วย — โมเดลเรียนจาก label ใน dataset ตรง ๆ (supervised cross-entropy) ไม่มี SSense ไม่มี API ภายนอก ไม่มี regex ปนในกระบวนการ
  • SSense มีบทบาทเฉพาะตอนใช้งาน (inference): เป็น tiebreaker ตัวท้ายของ /api/emotion เฉพาะเมื่อ regex ไม่เจออะไรและโมเดลไม่มั่นใจ
  • หลัง benchmark ล่าสุด (SSense แพ้ทั้งสองชุด) บทบาทของมันแทบไม่เหลือ — ตัดออกได้เลยโดยระบบไม่เสีย

🔬 Deep Check — บั๊กที่จับได้และแก้ทั้งหมด

  • v1 resume bug (โค้ดผมเอง): step += 1 ก่อนเช็ค skip → ทำงานเกินแผน 7466→9400 · v2 แก้: ลบ resume ทิ้ง รันเดียวจบ
  • v1 scheduler: ถูกสร้างใหม่หลัง resume ทำให้ LR decay คลาดจังหวะ · v2 แก้: ไม่มี resume = ไม่มีปัญหา
  • MPS dropout crash: SDPA บน Apple GPU ไม่รองรับ dropout · แก้: attn_implementation="eager"
  • loss weight คนละ device: weight tensor อยู่ CPU แต่ logits อยู่ MPS → RuntimeError · แก้: ย้าย weight ไป device ก่อนสร้าง loss
  • splitlines ทับบรรทัด: wisesight train มี 12 ข้อความหลายบรรทัด → label คลาดคู่ · แก้: split("\n") จับคู่ตามตำแหน่งจริง
  • class imbalance: v1 เมิน negative (16→neutral) · v2 แก้: class-weighted loss (neg น้ำหนัก 1.15×, pos 1.81×)
  • เครื่อง sleep: kill MPS session เงียบ ๆ 2 ครั้ง · แก้: caffeinate -ims + checkpoint resume + PYTORCH_MPS_HIGH_WATERMARK_RATIO=0

⚙️ สเปกการเทรน (v3 — ตัวที่ใช้งานจริง)

  • โมเดลฐาน: airesearch/wangchanberta-base-att-spm-uncased (105M params, ของ NECTEC)
  • วิธี: partial freeze — แช่แข็ง embeddings + 8 layers แรก, เทรน 4 layers ท้าย + classifier = 28.9M (27.5%)
  • ข้อมูล: Wisesight train 23,191 (pos 4,270 / neu 12,195 / neg 6,726) + thai_emotion ×20 → รวม ~25k
  • hyperparams: batch 32 · lr 3e-5 (warmup 6% + linear decay) · grad clip 1.0 · max_len 128 · loss มี class weights
  • device: MPS (GPU ของ M5) · เวลา 12.4 นาที · RAM ~4-5GB
  • เลือก best epoch ด้วย full val eval (2,454 ตัว) ทุกจุดจบ epoch

อ่านให้ถูก

SSense ชนะ in-domain (82 vs 76) เพราะเคสง่ายที่คำชัดมันเดาถูกตามโทน — แต่บนภาษาจริงที่ซับซ้อน (ทวิตเตอร์) มันร่วง 50% ในขณะที่โมเดลเราทำ 64.7% · และที่สำคัญ: เมื่อโมเดลเราพลาด เราแก้ได้ (เพิ่มข้อมูล/เทรนต่อ/ปรับ weights) แต่ SSense พลาดเมื่อไหร่เราทำอะไรไม่ได้เลย

🚧 ข้อจำกัดที่ยังเป็นความจริง

โมเดลยังแพ้ regex บน in-domain (76 vs 98) — และนี่ไม่ใช่ความล้มเหลว

เพรดานอยู่ที่ข้อมูล: in-domain มีแค่ 2k ประโยคนักเรียน (คูณ 20 = oversample ไม่ใช่ข้อมูลใหม่จริง) — benchmark ของ WangchanBERTa บน wisesight เต็มชุดอยู่ที่ 90-92% แปลว่าโมเดลฐานพอไหว ขาดแค่ข้อมูลโดเมนจริง · นี่คือเหตุผลของ Phase 2: เก็บแชทจริงจากผู้ใช้ — เมื่อมีแชทนักเรียนหลายหมื่นประโยค โมเดลจะแซง regex ได้เอง
