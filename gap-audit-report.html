🔴 CRITICAL — security holes all closed

#01OTP verification was client-side theaterFIXED

Before

  • OTP generated Math.random in the browser
  • correct code passed to the modal as a prop — visible in DevTools
  • client compares code itself → "verification" meaningless

After

  • server mints OTP (randomInt), stores sha256(code+pepper)
  • 10-min TTL · max 5 attempts · single-use
  • new POST /verify-otp — server decides, browser never holds the answer
#02Plaintext passwords in localStorageFIXED

Before

  • passwordHash field held the raw password
  • whole user store in localStorage — XSS = total takeover

After

  • team's final architecture: passwordless & anonymous (PDPA anon_id)
  • nothing credential-shaped exists to steal
  • chat content AES-256-GCM encrypted at rest (privacy.js)
Resolution: team's 156 newer commits replaced email/password auth entirely — verified stronger than my scrypt plan; kept their design.
#03LINE webhook signature never checkedFIXED

Before

  • verifySignature() defined… and never called
  • anyone could POST fake events → burn LLM tokens, poison DB

After

  • enforced with timingSafeEqual (no timing leak)
  • fail-closed: unset LINE_CHANNEL_SECRET → 401, not open season
  • smoke-tested: forged POST rejected live
#04History API — read anyone's chats, forge anyone's messagesFIXED

Before

  • GET returned 200 rows per guessed line_user_id
  • POST accepted any role (incl. system), any session title
  • no auth, no pagination, no rate limit

After

  • x-app-token gate (WEB_API_SECRET)
  • role allowlist user|bot, all fields length-capped
  • source forced server-side; client sends token header
  • DB rows AES-encrypted (team) + hashed user refs
#05Open email relays (send-otp / guardian-email)FIXED

Before

  • /send-otp mailed any address with a client-chosen OTP
  • guardian endpoint emailed any link provided → phishing from their domain
  • no rate limit → Gmail account suspension risk

After

  • server generates the code — client-supplied OTP ignored
  • email validation, strictLimiter 10/15min
  • SMTP-missing → clean 503, sendMail wrapped → 502
#06Guardian (PDPA) consent bypassable in 5 secondsFIXED

Before

  • one localStorage.setItem("approved","true") in DevTools
  • approval link was a bare client-generated token, no server binding

After

  • team's verification-code-to-parent flow kept & backed by server-side /verify-otp
  • client can no longer self-assert consent state
#07-08No CORS / no rate limiting on paid AI endpointsFIXED

Before

  • every API callable from any website
  • LLM/VQA/OCR proxies unthrottled → token drain

After

  • team: express-rate-limit global 120/15m + strict 10/15m
  • nginx + proxy-hop trust configured correctly
  • smoke-verified: 429s fire, headers present
